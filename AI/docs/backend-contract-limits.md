# 백엔드 ↔ 챗봇 필드 한도

`chat-analysis-v2` 요청에서 백엔드가 보내는 값과 챗봇이 받아 저장하는 곳의 한도입니다. 한쪽 숫자를 바꾸면 반대쪽과 이 표를 같이 고칩니다. 기준: 백엔드 `main` 203cb21, 2026-11-09.

| 필드 | 백엔드 | 챗봇 요청 검증 | 챗봇 저장 (`chatbot_logs`) |
| --- | --- | --- | --- |
| `message` | 4000자 (`ChatService`) | 4000자 (`MAX_CHAT_MESSAGE_LENGTH`) | `TEXT`, 원문 저장은 기본 꺼짐 |
| `barcode` | 255자 | 식별자 256자 | `VARCHAR(255)` |
| 상품명 | DB 컬럼 1000자 | 1000자 (`MAX_PUBLIC_PRODUCT_NAME_LENGTH`) | 저장 안 함 |
| 원재료 등 긴 텍스트 | DB `TEXT` 65535자 | 65535자 | 저장 안 함 |
| 분석 대상 수 | 본인 + 가족 | 21명 (`MAX_V2_PROFILES`) | 저장 안 함 |
| 대화 이력 | 20개, 한 건 10000자, 합계 40000자 | 같음 (`MAX_V2_HISTORY_*`) | 저장 안 함 |
| `policyVersion` | 현재 37자, 자체 테이블 100자 | 256자 (`Code`) | `VARCHAR(256)` (마이그레이션 `20261109`, 선택: 미적용 시 열 너비에 맞게 줄여 저장) |

- 앱이 요청 본문에 직접 넣는 상품(`product`)은 백엔드가 더 좁게 검사합니다: 상품명 500자, 원재료 16000자, 알레르기 26개 × 100자.
- 예전 형식(분석 컨텍스트 없는) 요청은 대화 이력을 50개, 한 건 4000자, 합계 20000자로 검사합니다. 백엔드는 이 형식을 쓰지 않습니다.
- `chatbot_logs`는 백엔드 Flyway가 아니라 `AI/migrations/*.sql`로 관리합니다. 챗봇은 시작할 때 `policy_version` 폭을 확인하고, 좁으면 적용할 마이그레이션을 경고로 남깁니다. 저장 실패 로그에는 MySQL 오류 번호와 컬럼 이름만 남깁니다.

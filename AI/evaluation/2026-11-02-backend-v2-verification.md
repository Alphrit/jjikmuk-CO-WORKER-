# chat-analysis-v2 AI 구현·검증 기록

## 변경 범위와 기준

AI 폴더 안에서 기존 요청과 v2 요청을 함께 처리하도록 추가했다. 프론트·백엔드·`.env`·실제 DB·AWS를 수정하지 않았다. GitHub push/배포도 하지 않았다. 새 필수 환경변수·라이브러리·DB migration은 없다.

첨부 ZIP 기준 백엔드 커밋 `eae67ecfde34f3ba1a8296c7ae2dd7b74e94d38a`는 현재 작업 폴더의 원격 저장소가 아닌 `KW-coworker/JJIKMUK-Backend`에서 확인했다. 해당 커밋의 ChatService, ChatProfileResolver, ProductService, RecommendationDto, AnalysisSelection, ProductDataQuality 및 관련 테스트를 읽고 실제 필드/enum을 대조했다. 누락된 `analysis` 구조를 임의로 가정하지 않았다.

## 구현

- 닫힌 타입으로 `analysisContext`, 개인별 `profileAnalyses`, 식단 판정·자료 근거를 검증한다. 상태·플래그 모순, 개인 키 중복/누락, 그룹 결과가 개인 충돌을 숨기는 경우를 거절한다.
- `profileKey`로 연결하므로 이름이 같거나 `self:41/family:41`처럼 숫자 ID가 같아도 결과가 섞이지 않는다. 다음 요청의 `request:0`에 지난 요청의 임시 알레르기·채식 허용 정보를 옮기지 않는다.
- 백엔드 상품 판정은 검증된 상태값에서 설명을 구성한다. 과거 답변, 요청 자유문 `message`, 저장된 vegan boolean으로 판정을 덮어쓰지 않는다. 개인 DANGER/PASS/UNKNOWN과 식단 PASS/MISMATCH/UNKNOWN을 분리한다.
- 전원 OFF는 NOT_EVALUATED, 상품 미선택은 판정 없음으로 처리한다. 한 사람의 충돌을 모든 사람의 충돌로 복사하지 않는다.
- 서비스 토큰과 일치하는 버전/contextId를 확인하고, 실제 v2 처리가 끝난 응답에만 확인 헤더를 반환한다. 기존 외부 AI 동의 서명 규격 v1은 변경하지 않았다.
- 일반 RAG·추천·비교·레시피·저장/조회/삭제는 기존 구현을 사용한다. 바코드 하나의 판정을 다른 상품이나 생성 재료의 판정으로 쓰지 않는다.
- v2 21명과 이력 20개/각 10,000자/총 40,000자를 지원한다. 기존 요청 20명 및 이력 한도는 유지한다. 긴 합산 이름과 레시피의 21명 결과 배열을 보완했다.
- 상품 검색은 실제 카드를 찾았으면 찾았다는 안내와 재선택 흐름을 제공한다. 공개 상품 스키마에 담을 수 없는 입력은 출력 중 500이 되기 전에 422로 거절한다.

## 검사 결과

| 검사 | 결과 | 범위 |
|---|---:|---|
| 전체 pytest 1차 | 3,017 통과 | 기존 2,938 + 당시 신규 v2 79 |
| 전체 pytest 2차 | 3,021 통과 | 집단/개인 모순 검증 4개 추가 이후 |
| 최종 관련 검사 | 127 통과 | 최종 v2 96개 + 공개 응답/동의 서명/저장 대화 검사 31개 |
| 실제 uvicorn/HTTP + OpenAI | 24/24 | 합성 프로필·메모리 저장소, 실제 RAG 질문 2건 포함 |
| 마지막 검색 수정 후 실제 HTTP | 22/22 | 외부 AI OFF, 상태/본문/동작을 검사 |
| 변경 범위 | AI 밖 변경 0 | 작업 시작 시 파일 해시와 대조 |
| diff 검사 | 통과 | `git diff --check -- AI` |

전체 2차 실행 이후 추가한 입력 타입/크기 및 검색 안내 변경은 최종 관련 검사에서 다시 검사했다. `3,021 + 127`을 서로 다른 테스트 수로 합산하지 않는다. 신규 v2 테스트의 최종 수는 96개다.

신규 검사는 0/1/2/21명, 동명이인, 개인 결과 순서 변경, 숫자 ID 충돌, 엄마→아빠 전환, 미선택 인물 질문, 현재 발언의 새 조건, 과거 PASS/악성 설명 문자열 무시, 알레르기·식단 조합, 개인 결과 보존, 상품 변경/미선택, 응급 우선, 레시피/비교/검색/레시피 재안내, 저장 대화 재시도/재조회/삭제, 잘못된 토큰·헤더·서명·nonce 재사용, 한도 초과·타입 오류를 포함한다. 새 테스트는 기존 기대값을 고쳐 통과시키지 않았다.

## 실제 OpenAI 확인

로컬 uvicorn 서버에 합성 프로필과 본문 서명으로 다음 두 질문을 보냈다. 운영 키/서명/로그인 토큰은 결과 파일에 기록하지 않았다.

1. “무설탕과 무가당의 차이가 뭐야?” → HTTP 200, `answer_source=rag`, 무당/무가당 차이에 해당하는 출처, 약 20.5초.
2. 같은 문맥의 “그럼 칼로리는?” → HTTP 200, `answer_source=rag`, 감미료·열량에 해당하는 출처, 약 10.1초.

두 답변을 읽어 질문에 맞는 내용과 출처를 확인했다. 동의 없는 동일 계열 질문은 외부 호출 없이 응답했다. 모의 제공자 테스트에서는 검색 → LLM 생성 → 독립 근거 검증을 거쳐 답변을 채택하는 흐름과 잘못된 서명/철회/재사용 시 호출 차단도 확인했다. 실제 요청의 생성문 채택/검토 원문 대체 비율이나 모든 문장 품질을 이 두 사례만으로 일반화하지 않는다.

## 남은 공동 연결 및 제한

1. 첨부 기준 백엔드 AiChatClient는 v2 확인 헤더만 전송한다. 백엔드 담당자가 내부 토큰과 최종 JSON 바이트에 대한 외부 AI 동의 서명을 v2 경로에도 연결해야 한다.
2. 실제 로그인 백엔드 → AI → 모바일 앱 전체 경로, AWS 배포, 최신 운영 MySQL은 이번에 실행하지 않았다. 실제 서버 검사는 로컬 메모리 저장소이며 OpenAI만 실제 외부 호출이다.
3. AI가 이름으로 새 상품을 찾거나 채팅에서 새 조건을 들었을 때 현재 바코드의 판정을 그대로 재사용하지 않는다. 새 상품/조건에 대한 백엔드 재요청이 필요하다. 추천 후보 전체를 백엔드 공통 판정으로 바꾸는 계약은 이번 BARCODE_ROW 규격에 포함되지 않는다.
4. v2 ProductDto에는 영양 기준량 정보가 없어 한 봉지/1회분 수치를 추정하지 않는다. 프로필/상품 표시의 공통 크기 제한은 [연동 문서](../docs/backend-analysis-v2.md)를 기준으로 양쪽에서 검증해야 한다.
5. 운영자가 별도로 추가한 누적 외부 호출 한도·공유 nonce 저장소가 있다면 운영 브랜치와 병합해 유지해야 한다. 이 작업에서 해당 상태 파일을 생성·초기화하거나 운영 참고본으로 기존 기능을 덮어쓰지 않았다.

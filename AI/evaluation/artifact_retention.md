## 복원 및 공유

필요한 파일을 보관 폴더에서 `results/`로 되돌리면 복원됩니다. 같은 이름의 파일이 있으면 덮어쓰지 말고 먼저 비교합니다. 과거 검색 평가를 비교하는 두 문서는 이동한 보관 경로를 사용하도록 갱신했습니다.

`results/`와 하위 보관 폴더는 모두 `.gitignore` 대상입니다. **코드를 커밋해도 이 결과 파일·해시 목록이 GitHub에 백업되지는 않습니다.** 팀 공유에는 `service_acceptance.md`의 검증 요약을 사용하고, 원본 결과가 필요하면 개인정보·질문 원문·내부 진단 포함 여부를 검토한 뒤 별도로 전달합니다. 원본 전체를 `git add -f`로 올리지 않습니다.

## 앞으로의 기준

새 실행 결과는 기존 평가 명령이 `results/`에 생성합니다. 이전 결과를 현재 구현의 통과 근거로 혼동하지 않도록 실행 날짜·설정·실제 외부 호출 여부를 함께 기록합니다. 정리할 때는 실행 중 생성된 결과를 피하고, 명시적인 파일 목록과 해시를 확보한 뒤 별도 보관 폴더로 옮깁니다. 자동 영구 삭제는 추가하지 않습니다.

## 유지하는 호환 코드

대화 저장소의 `expires_at` 컬럼, `retention_days=None` 계약, 삭제 없이 0을 반환하는 `purge_expired()`는 기존 호출·DB 호환용입니다. 자동 만료 기능이 아닙니다. 신규 SQLite DB에는 사용하지 않는 만료 인덱스를 만들지 않지만, 기존 DB의 컬럼·인덱스는 임의로 제거하지 않습니다.

활동 저장소의 레거시 `histories` 호환 경로와 과거 SQL 마이그레이션도 유지합니다. 기본/API 실행에서는 레거시 활동 쓰기가 비활성화되어 있으며, 실제 사용자 채팅방 저장과는 별개입니다. 제거하려면 백엔드 사용 여부와 배포된 DB 스키마 확인이 먼저 필요합니다.
